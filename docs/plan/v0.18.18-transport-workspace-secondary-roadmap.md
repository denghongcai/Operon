# Transport, workspace and secondary runtime hardening

Status: In progress. Source baseline: `ce1dfe6` / public `v0.16.10`.

This follow-up covers report P5, P8 and every P10 finding. Parallel-read
throughput tuning, P3 attribute caching, P9 directory pagination and store
compaction are not included. Internal batch identifiers are not public versions.
The requested end state includes implementation, full acceptance, commit/push,
and a verified public release, provisionally `v0.16.11`.

## Phase 132: v0.18.18 Transport liveness

Status: In progress.

Initial implementation: Rust endpoint transport configuration, CLI global
timeout overrides, daemon/client keepalive and adaptive windows, ordinary CLI
and mount request deadlines, and CLI download progress bounds are present.
Config explain exposes transport values. Focused Rust config/client/CLI tests
passed (10/11/54 unit tests plus 10 compiled CLI integration tests); local TCP
tests require execution outside the network sandbox. SDK endpoint timeout and
keepalive settings, deadline middleware and 19 tests/typecheck now pass. The
real TCP fixture verifies short-deadline cancellation and a longer-deadline
successful call on the same channel. Docs/help/skills synchronization passed.
Network fault acceptance, long-lived stream header bounds and complete release gates
remain pending. No phase has been marked complete.

Additional local acceptance now passed: real TCP transport blackholes with RPC
deadlines disabled, configured 1s keepalive interval/timeout, explicit recovery,
and unary headers followed by an incomplete protobuf body. Shared DeadlineChannel
enforces the total local deadline through body completion. Full native gates
remain pending; ordinary metadata alone is not used as proof of body liveness.

- Add bounded ordinary RPC deadlines shared by Rust CLI/mount and SDK, while
  preserving auth/context metadata. File transfers need a distinct policy;
  watch/log streams, PTY and TCP/UDP tunnels must not inherit a short overall
  lifetime. Bound stalled file-transfer progress, not legitimate session idle.
- All timeout values must be configurable for high-latency international
  links. Per-node YAML settings and CLI per-invocation overrides take priority
  over defaults; define zero/disable semantics and test non-default values.
  Expose equivalent SDK endpoint options and daemon keepalive settings.
- Configure HTTP/2 keepalive and bounded ping timeout on client/server; expose
  opt-in adaptive flow control where supported. Keepalive detects dead transports,
  not a live server whose handler never completes, and does not replace deadlines.
- Exercise a reachable but non-responsive peer, stalled response bodies,
  healthy slow transfer, cancellation, reconnect and long-lived streams.
  Verify mount failures map to errno and requests do not replay mutations.
- Document defaults/limitations and add focused validation to runtime CI.

## Phase 133: v0.18.19 Workspace root reuse

Status: In progress. Phase 132 local fault tests passed; final native/release
acceptance remains shared with Phase 136.

- Introduce a daemon-owned resolver that caches canonical root and Linux root
  descriptor; keep per-target containment and leaf-symlink checks.
- Define fail-closed behavior for root rename/replacement/deletion; do not
  validate against a cached descriptor then open through a different root.
  Preserve non-Linux fallback and mutation commit-time revalidation.
- Remove redundant directory setup only where existing-parent semantics allow.
- Test traversal, symlink swaps, root changes, absent ancestors, permissions,
  read/write/delete/rename/copy and cross-platform startup diagnostics.
- Measure syscall counts and completed ops/s against the same-correctness
  baseline. Absolute timing remains supporting evidence.

## Phase 134: v0.18.20 Bounded streaming and mount runtime

Status: In progress. Phases 132–133 local implementation/tests are progressing;
final native and release acceptance remains in Phase 136.

- Stream CLI file uploads without read_to_end or constructing all protobuf
  requests up front; make byte/stdin chunk production lazy and bounded.
- Make raw stdout filesystem reads binary-safe; preserve documented JSON text
  behavior and binary-safe --output. Test quiet/output/error contracts.
- Remove avoidable chunk copies where compatible with generated/public API
  types; explicitly document any remaining required wire-boundary copy.
  File upload, stdin upload and daemon download readers now fill owned protobuf
  vectors directly; borrowed byte chunks and serialization retain ownership costs.
- Give mount transport a continuously driven multi-thread runtime and a stable
  sync/async bridge without spawning an OS thread per nested call. Validate
  concurrent access, timers, cancellation and safe runtime destruction.

## Phase 135: v0.18.21 Secondary allocation cleanup

Status: In progress. Depends on final Phase 134 acceptance.

All listed implementations are present. A clone-count regression proves a
10-record page from 10,000 retained records performs exactly 10 clones. Typed
prepared records retain the same JSON line format without intermediate trees or
event copies; serialization and durable queue waiting occur outside the audit
mutex, with block_in_place preserved for multi-thread Tokio callers. Mixed-record,
restart, corruption and sticky write-failure tests passed. Final allocation/ops
evidence and native acceptance remain pending.

- Cache mount trace enablement rather than querying the environment per event.
- Clone only requested audit pages, preserving order, tokens and errors.
- Avoid audit JSON-tree construction/deep cloning before store enqueue; retain
  complete durable events, ordering and visible persistence failures.
- Avoid store loader JSON deep copies; verify mixed record restoration and
  corrupted-tail recovery. Do not add compaction or change retention here.
- Add regression tests for every P10 sub-item and record memory/ops evidence.
