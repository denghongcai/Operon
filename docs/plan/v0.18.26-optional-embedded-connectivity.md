# Optional embedded connectivity (Phases 154–159)

Status: In Progress. User approved PoC closeout, production implementation,
complete regression/native/online CI verification, README guidance and a
verified public release. MSRV may be upgraded deliberately; connectivity must
remain opt-in. This is an internal batch identifier, not the public version.

## Required architecture

Existing grpc/grpcs host addressing remains the default and supports localhost,
LAN, DNS and VPN-provided routes without a new networking process. Optional
iroh is embedded in Operon, not spawned as a sidecar. It owns authenticated
connections, not capability authorization or business RPC semantics. Logical
node_id remains independent of persistent cryptographic endpoint identity.
No silent backend fallback or automatic public infrastructure enrollment.
No custom NAT/relay protocol, IP mesh, routing or VPN stack. Future embedded
backends may implement the connection boundary without restoring the removed
user-facing provider model.

Native tonic incoming/connector streams carry the current HTTP/2 gRPC protocol;
production must not ship the PoC TCP bridge. Preserve token/policy, workspace
containment, audit context, write preconditions, offsets/EOF, exec/session/service
stream semantics and cancellable mount shutdown. Endpoint/accept/connection
tasks must be bounded, owned and joined. Timeouts and relevant transport limits
must be configurable, including finite connection/address-lookup waits over
international links; disabling deadlines must not disable shutdown cancellation.

## Phase 154 — PoC closeout and implementation contract

Fix resource ownership, unexpected-error propagation, example task ownership,

## Phase 155 — MSRV and embedded transport boundary

Upgrade workspace MSRV/toolchain consistently to an iroh-supported baseline
(initial target Rust 1.91), including CI, GNU/musl/native packaging and pinned
container builders. Retain edition unless migration is actually needed.
Implement reusable owned iroh endpoints/QUIC I/O and direct connector paths,
with tests and no networking dependency in operon-core. Keep old grpc/grpcs
configuration source-compatible; pin supported dependencies in the lockfile.

## Phase 156 — Native daemon and client integration

Implement explicit opt-in daemon listener and per-node iroh connection settings,
persist private identity securely across restarts, validate peer addressing,
configure relay/address lookup explicitly and keep logical node identity stable.
Use native incoming rather than TCP forwarding. Integrate Rust CLI/mount,
onboard/config/doctor/discovery/help and service startup. Reject unknown or
disabled backends clearly; preserve old-only and mixed-backend behavior.
Validate identity mismatch, unauthorized clients, replacement/rotation and
resource/cancellation/error boundaries without weakening existing authorization.

## Phase 157 — Actual relay/network and SDK acceptance

Run a self-hosted iroh relay in a scoped Docker topology. Separate client/server
network namespaces and routes, explicitly deny their direct peer traffic and
prove traffic really traverses the relay (path/counter evidence). Then enable
direct traffic and verify upgrade, relay loss/recovery, denied UDP and interrupted
streams. Separate NAT traversal evidence from ordinary Docker bridge reachability.
Do not depend on public relay availability for mandatory gates. Re-run these
actual scenarios in hosted CI, retaining artifacts and bounded configurable
timeouts; compile-only checks are insufficient. Exercise real fs/exec/PTY/service
and mounted I/O where supported, not just synthetic echo. Decide and implement
the TypeScript SDK's embedded connection path without external processes; test
the public SDK directly, not merely a Rust substitute. Native Linux GNU/musl,
Alpine/OpenRC, macOS and Windows remain required support targets.

## Phase 158 — Full regression, measurements and user documentation

Run full Rust workspace/all-targets, SDK typecheck/build/tests, all consolidated
core/SDK/runtime/system validations, fmt/strict Clippy and native CI. Verify both
disabled/default direct addressing and opted-in/mixed transports. Test streaming,
connection/response deadlines, zero-deadline shutdown, lost peers and daemon
restart, authorization and traversal denial, no mutation replay, range/EOF and
concurrent mount semantics. Record matched ops/s-first direct/relay measurements
and regressions without universal performance claims. README must explain
opt-in setup, pairing/identity, networking, relay self-hosting/lookup dependencies,
timeouts, supported targets/SDK, diagnostics and unchanged VPN/LAN usage.
