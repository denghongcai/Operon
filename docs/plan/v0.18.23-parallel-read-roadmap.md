# Parallel read optimization (Phases 142–145)

Approved implementation scope: improve remote parallel reads using measured
completed-operation throughput, without weakening authorization, audit,
workspace containment, EOF semantics or write-through consistency.

## Phase 142 — Reproducible baseline

Status: Completed. Unchanged Rust 1.88 release binaries were retained before
runtime edits; matched three-trial fresh-mount local and delayed comparisons
include verified operation counts, payload hashes, RPC/network and resource evidence.

Build unchanged release binaries before modifying runtime code. Record source
revision, dirty state, binary hashes, actual transferred bytes and file hashes.
Use isolated Docker daemon/client containers and fresh mounts for each cold
client case. Compare same/distinct files at 1/2/4/8/16 readers, sequential and
random workloads, and local/latency-injected transport. Count one complete file
transfer or one verified random read as an operation, not a batch or RPC.
Alternate baseline/candidate ordering across at least three trials. Retain
ops/s, latency, network bytes, audit RPC counts and resource evidence separately.

## Phase 143 — Bounded configurable mount concurrency

Status: Completed. Validated config/CLI limits, cross-platform rejection of
Linux-only workers, configurable queue/RPC deadlines and cancellation tests
are implemented. Linux default remains four workers; eight is opt-in.

Expose validated Linux FUSE worker count and read concurrency/byte budgets via
config.yaml and CLI overrides. Preserve macOS/Windows behavior and reject
unsupported platform-specific overrides rather than silently ignoring them.
Keep transport timeout configuration working, including high-latency networks.
Measure before selecting new defaults; do not assume more threads always wins.

## Phase 144 — Evidence-led read-path optimization

Status: Completed. Fresh per-RPC file reads use one blocking task and retain
authorization/resolver/audit plus short-read/EOF semantics. No new cache or
kernel tuning was necessary; default worker trials improved the target case 19%.

Reduce measured per-range overhead while retaining per-request authorization
and audit. Evaluate one bounded blocking file-read task instead of multiple
Tokio file open/seek/read transitions. Evaluate kernel request/queue negotiation
only if request measurements justify it. Do not add persistent fd/content
caches, alter consistency, or add connection pools without supporting evidence.
Any asynchronous FUSE dispatch must have bounded lifecycle and unmount cleanup.

## Phase 145 — Regression and performance acceptance

Status: Completed (source/local acceptance). Full local suites, real Linux FUSE
and macOS/Windows source cross-compilation passed; final release-binary local
and delayed three-trial confirmation and evidence closeout are complete.
See `docs/quality/parallel-read.md` and its machine-readable evidence for all
trials, pinned binary hashes, opt-in gains and disclosed regressions. Native
platform/public release gates were separate at this checkpoint and subsequently
completed in Phase 146 for published v0.16.13.

Validate unit/CLI/config tests, error/EOF/range boundaries, concurrent mutations,
workspace replacement and traversal protections, timeouts, bounded memory and
real Linux FUSE behavior. Run consolidated Rust/SDK/runtime/Linux validations,
format/clippy and docs/help/skills synchronization. Report matched ops/s ratios
and variability, including regressions. Target recovering the historical
distinct-file four-reader 10–15% regression without materially regressing
single-reader/random operations. No fixed speedup is promised.

Public release is a separate exact-SHA gate; this roadmap does not mark native
macOS/Windows/Alpine or public artifact acceptance complete from local tests.
That separate gate is now completed: see
`docs/plan/v0.16.13-release-publication.md` for exact-SHA source and downloaded
public binary evidence. No work remains in Phases 142–146.
