## Phase 148 — Formal bounded read scheduler

Replace the experimental feature with a maintained asynchronous read scheduler
and config/CLI read-mode controls, preserving an explicit synchronous fallback
mode for operators. Linux default async activation requires the subsequent
acceptance gates. Keep four Linux callback workers, configurable RPC/byte
limits and existing ordinary RPC deadlines; do not derive concurrency blindly
from CPU count. Bound pending tasks with validated configurable limits and
cancellable backpressure rather than unbounded spawn or a blocking-RPC fallback
that can prevent shutdown. Queue admission must be covered by the configured
deadline; zero deadline must still allow shutdown cancellation. Normalize paths
before dispatch, keep daemon authorization/resolution/audit, EOF/error semantics
and write-through consistency. No kernel tuning, content/fd cache or schema
change. Unix adapter support decisions require actual platform acceptance;
Windows retains its native WinFsp dispatch rather than pretending it is FUSE.

## Phase 149 — External unmount, cancellation and lifecycle repair

Repair the existing external `fusermount3 -uz` plus open-file/in-flight-read
EINVAL failure, including synchronous mode. Detect external detachment without
unmounting a replacement filesystem at the same path. Cancel queued and active
reads before teardown, own task lifetimes, and join both task and background
session completion. Do not silently ignore EINVAL or detach a running session
thread. Define open-descriptor disconnection behavior and clean exit status.
Assess low-level FUSE INTERRUPT routing and implement request cancellation
where supported; explicitly validate behavior rather than claiming cancelled
futures imply interrupted disk I/O. Any shutdown/admission timer must be
configurable or derived from existing configured transport limits.

User-approved boundary (2026-10-10): ordinary external detach/replacement remains
required; disclose that concurrent privileged overmount between identity check
and path-based unmount is not atomically protected. Pinned-FD/cwd and move_mount
diagnostics rejected unsafe substitutes. The user accepted publishing with this
limitation after all other gates, not skipping lifecycle/platform tests.

## Phase 150 — Correctness, saturation and platform acceptance

Unit/config/CLI boundaries, queue/byte saturation, deadline-disabled cancellation,
RPC errors, connection loss, concurrent reads/mutations, path normalization,
permissions, offset/EOF/short-read behavior and exactly-once replies. Reproduce
the failed live probe until it passes in both sync and async modes, without
weakening assertions. Verify normal, external, busy/open-handle and in-flight
unmount with actual FUSE; test remount/replacement races and task/descriptor
cleanup. Run full Rust/SDK and all consolidated validation groups, fmt/clippy,
docs/help synchronization and native platform gates including x86_64/arm64
Alpine/FUSE/rebooted OpenRC, macOS FUSE-T and Windows WinFsp. Do not substitute
cross-compilation or unit-only cancellation for live acceptance.

## Phase 151 — Final ops-first performance and default decision

Retain Phase 147 data as historical prototype evidence. Build final production
binaries and compare pinned same-toolchain synchronous baseline against the
final implementation: fixed four workers, 8/16/32 RPC limits, 1/4/8/16 readers,
same/distinct/random reads, local and injected delay, at least three alternating
trials. Keep the same-RPC-limit increased-sync-worker control. Count verified
completed operations; retain RPC/network, resource and lifecycle evidence and
regressions. No universal speedup or hard RSS promise. Choose/document defaults
only after final measurements; explicit configurable sync mode remains available.
