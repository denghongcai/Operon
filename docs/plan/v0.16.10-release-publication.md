# v0.16.10 Runtime Correctness and Performance Release

Status: In Progress.

Publish the Phase 126–130 implementation on the existing public v0.16 patch
line. Internal v0.18.13–v0.18.17 batch identifiers are not artifact versions.
Performance acceptance is based primarily on completed operations per second;
mean/p50/p95/p99 latency and byte throughput are supporting measurements.

Scope:

- Complete store, range/transport, replacement failure/ACL, pagination and
  mount metadata acceptance, including native macOS/Windows tests.
- Align Rust, SDK, protocol reporting, examples and workflow inputs to
  `0.16.10` / `v0.16.10`.
- Commit and push implementation to main, require exact-commit CI and CodeQL,
  cross-platform live mount and Windows runner smoke before tagging.
- Build Draft Release assets, publish, then verify public checksums, binaries,
  installation/service management and README Quickstart.
- Record exact commit, workflow run IDs and outcomes before marking complete.

Local evidence:

- Workspace tests, strict all-target Clippy, Rust formatting and SDK
  typecheck/public API/test/build passed.
- Linux failure-injection, require_absent race, POSIX ACL, symlink and TCP
  pagination-connection fixtures passed; native counterparts are wired in CI.
- Two-round ops/s benchmark evidence: `/tmp/operon-phases-7habothy`. Persistent
  writes: 544/547 -> 878/947 ops/s; create/write/close: 234/247 -> 334/353 ops/s;
  64MiB CLI reads: 1.61/1.72 -> 8.46/9.27 file ops/s. Distinct parallel FUSE
  reads regress 13–19%; no generic FUSE read speedup is claimed.
- Candidate store has no bad lines, restores exec/log/audit on both restarts
  and retains full 4MiB exec output. Default Always sync is unchanged.

Remote validation and publication evidence will be appended as gates finish.
No pending gate is counted as passed merely because it is dispatched.

Gate-driven fixes:

- First CI run `37632532022` passed native macOS, but newer Clippy flagged
  async-trait generated `must_use` annotations. The narrow lint exemption is
  confined to generated protocol types, not handwritten production code.
- Windows installation logs showed Chocolatey feed HTTP 504 and "0/0 packages"
  despite proceeding to build; this was not an SDK registry migration. Added
  a shared installer using the official pinned WinFsp v2.1 MSI with SHA256 and
  Authenticode verification, explicit MSI exit checks and SDK/registry checks.
  CI, live mount, Windows runner and release builds share that installation.
- Initial live mount run `37632611370` passed every enabled hosted job, including
  macOS FUSE-T and Windows WinFsp. Exact-commit gates must be rerun after fixes.
- Release inspection found seven existing JS dependency alerts. Updated
  grpc-js to 1.14.5, Vitest/mocker to 4.1.11, nanoid to 3.3.18, PostCSS to
  8.5.23 and source-map-js to 1.2.2. SDK typecheck/public API, all 16 tests and
  build passed after the patches. Full and production `pnpm audit --json`
  report zero known vulnerabilities. These are compatible patch updates.
