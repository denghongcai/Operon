# v0.18.12 Architecture Boundary Cleanup

Status: Completed.

## Goal

Reduce cross-module coupling identified by the post-v0.16.8 architecture
review without changing the runtime protocol or public CLI and SDK behavior.

## Scope

1. Aggregate daemon execution records, logs, event channels, cancellation,
   stdin, and ID allocation behind `ExecRegistry`.
2. Define `operon-grpc-client` explicitly as a shared transport crate rather
   than a domain client.
3. Move `NodeEndpoint` ownership to the core runtime model while preserving the
   existing config re-export for compatibility.
4. Move protocol conversion implementations out of the protocol crate
   entrypoint, leaving `lib.rs` as the stable generated-type and conversion
   facade.
5. Extract TypeScript SDK graph execution and gRPC client pooling from the
   stable `OperonClient` public entrypoint.
6. Use domain-qualified `operon-core` paths in the touched runtime boundaries
   while retaining root re-exports for compatibility.

## Progress

- Added `ExecRegistry` and routed normal exec and interactive exec session
  registration through it.
- Removed the `operon-network -> operon-config` dependency and the
  `operon-grpc-client -> operon-network` dependency.
- Moved `NodeEndpoint` to `operon_core::runtime` and retained
  `operon_config::NodeEndpoint` as a compatibility re-export.
- Extracted protocol conversion implementations to `conversions.rs` while
  preserving all crate-root exports.
- Added SDK `GrpcClientPool` and `runGraph` internal modules without changing
  the package public API.
- Added focused `ExecRegistry` coverage and retained existing protocol and SDK
  contract coverage.
