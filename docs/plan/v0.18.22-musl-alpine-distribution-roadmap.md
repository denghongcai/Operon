# Linux musl / Alpine Distribution Roadmap

Status: Planned. Baseline: public `v0.16.11`, release source
`79132f27a306e8737cec802a310278c14c310e13`.

The user approved additional Alpine-compatible builds, not replacement of the
existing GNU/glibc archives. Phases 137–141 cover implementation, native runtime
acceptance and verified public distribution. This planning task adds no builds
or new support claim. Internal v0.18.22–v0.18.25 names are not public versions;
the prospective public release is `v0.16.12`, confirmed before version alignment
and tagging. No version bump is included in writing this plan.

## Scope and artifact contract

| Architecture | Rust target | Additional release asset |
| --- | --- | --- |
| x86_64 | `x86_64-unknown-linux-musl` | `operon-<tag>-linux-musl-x86_64.tar.gz` |
| arm64 | `aarch64-unknown-linux-musl` | `operon-<tag>-linux-musl-arm64.tar.gz` |

- Each archive contains `operon`, `operond`, documentation and license using
  the existing installation layout. Require fully static ELF outputs; choosing
  a musl Rust target alone is not proof of static linking.
- Preserve current glibc names/baseline, ARMv7 GNU support, macOS/Windows and
  SDK artifacts, as well as all their existing acceptance gates.
- Intended Alpine support: CLI, foreground daemon, filesystem/exec/PTY/service
  forwarding and real FUSE mount, only after both architectures pass acceptance.
- Static linking does not remove kernel, `/proc/self/fd`, `/dev/fuse`, mount
  permission or non-root mount-helper requirements.
- Add OpenRC supervision through `operond service`, retaining existing systemd
  behavior and making backend/scope/privilege differences explicit.
- No apk packaging, Cloudsmith, ARMv7 musl, networking changes
  or parallel-read tuning. Current released glibc archives remain unsupported
  on Alpine until additional musl artifacts are published and verified.

## Phase 137: v0.18.22 musl Build and Artifact Contract

Status: In progress. Dependency/toolchain audit and local build setup started.

Initial Alpine runtime candidates are 3.22 and 3.23, resolved to image digests
`sha256:5291449c3df73caf6ed85e649dec1b9e818b39a5d8c871e97afc13e9cd5e8fa8`
and `sha256:85fe1e81d6758c208f3e1eed4338a1997e19d4be002d4dd32d3100c9a8c010a0`.
They become a support baseline only after actual acceptance; current support
claims remain unchanged. Local host has musl-gcc and `/dev/fuse`; no local
native arm64 execution is inferred from the x86_64 host.

Pinned initial native builder: `rust:1.88.0-alpine3.22` at
`sha256:9dfaae478ecd298b6b5a039e1f2cc4fc040fc818a2de9aa78fa714dea036574d`,
Rust 1.88.0, GCC 14.2.0-r6 and binutils 2.44-r2. Install musl/musl-dev
1.2.5-r12 and protobuf generator 29.4-r0 explicitly; the base image's musl
1.2.5-r10 without development CRT is insufficient for proc-macro linking.
`scripts/build-musl-release.sh` enforces native
architecture and `scripts/verify-musl-static-binaries.sh` rejects interpreters,
dynamic dependencies and GLIBC symbol requirements. Initial host musl-gcc
static-PIE output failed this gate and crashed on Alpine; Rust's bundled CRT
with the normal cc linker passed and started on Alpine 3.22.6. Full x86_64
musl workspace tests passed locally and the native Alpine x86_64 build passed.
The new `Alpine musl Acceptance` workflow builds/tests both native architectures
and smokes both pinned runtime releases. Arm64 and real runtime/FUSE/OpenRC
acceptance remain required; initial workflow smoke is not full release proof.
Native x86_64 Alpine workspace tests and 3.22 runtime integration passed;
`scripts/package-musl-release.sh` produces and smoke-tests the agreed static
archive layout. Build verifier regression tests are wired into the core group.
The existing integration script accepts an explicit packaged-binary directory;
its default source build/unit-list coverage remains unchanged. Packaged runs
do not pretend to check source unit-test inventory; native workspace tests run
separately in the workflow.

Tasks:

- Audit target-specific dependencies and linker requirements: vendored fuser,
  portable-pty, libc calls, protobuf generation and C toolchains. Do not disable
  mount functionality or accidentally enable Linux dynamic libfuse linking.
- Pin reproducible build images/versions/digests and Rust/C toolchains; build
  both targets with the lockfile and record commands/environment. Cross-builds
  are allowed but do not replace runtime acceptance.
- Inspect both ELF outputs for interpreter, `DT_NEEDED` and GLIBC references.
  Require fully static binaries; stop and revisit the contract explicitly if
  dynamic dependencies prevent that, rather than silently changing packaging.
- Select and record a supported minimum Alpine release plus a second test
  release from actual dependency/runtime evidence; pin acceptance images.
  Do not imply compatibility with every historical Alpine or other musl OS.
- Define archive/checksum contracts and update distribution decisions with
  planned versus released states, without initial package/protocol version bumps.

Exit criteria: both locked builds and static ELF checks pass; both archive
layout/version/help smokes pass; dependencies, toolchain and Alpine baseline
are recorded; focused CI validation exists and current glibc builds remain green.
Build success or `--version` alone does not establish Alpine runtime support.

## Phase 138: v0.18.23 Alpine Runtime and Live FUSE Acceptance

Status: In progress. Native x86_64/arm64 build, workspace tests and packaged
integration passed on both pinned Alpine releases in run `37793265644` at
`bef76d2cf7283d5a4e7b101bfbd8f6dce469f684`. Local x86_64 root live FUSE passed
on 3.22; non-root live FUSE passed on 3.22 and 3.23. Native arm64 live FUSE and
comparative performance/failure acceptance remain mandatory.

Tasks:

- Run packaged binaries on both native architectures against the pinned Alpine
  baseline and second release. Emulated smoke supplements but cannot be sole
  evidence for runtime/live-mount release gates.
- Validate onboard/config/token permissions, readiness/auth/policy/doctor,
  filesystem range/stream/mutation integrity, exec/PTY/output/cancellation,
  TCP/UDP forwarding, audit/store durability and restart recovery. Include
  Alpine shell defaults/PATH behavior and foreground startup without systemd.
- Retain deadline/keepalive, containment/root-change and interrupted upload
  tests. Non-default/disabled timeout settings must work; harness deadlines
  remain configurable for slow CI and international links.
- Exercise actual mount/read/write/truncate/rename/delete, binary/range integrity,
  errno mapping, cancellation, clean unmount and daemon-restart recovery.
  Test root and non-root mount-helper paths with the required utility installed.
- Scope privileged fixtures to explicit devices/capabilities and owned resources
  with reliable teardown. Missing `/dev/fuse` fails the required gate, not a
  successful skip. Do not use fake-systemd tests as OpenRC support evidence.
- Compare representative glibc/musl filesystem and exec workloads primarily in
  ops/s; retain RSS/timing as supporting evidence, data integrity and disclosed
  regressions. Do not expand this phase into unrelated performance tuning.

Exit criteria: real runtime and live FUSE tests pass on both native architectures;
record binary hashes, images, runner identity and logs. Capability blockers remain
explicit and prevent completion rather than silently narrowing approved scope.
Clean up only fixture-owned processes, mounts, containers and temporary files.

## Phase 139: v0.18.24 OpenRC Service Management

Status: Planned. Depends on Phases 137–138.

Tasks:

- Add OpenRC-backed `operond service install/start/stop/status/uninstall` and
  boot-runlevel enablement using actual OpenRC commands and service supervision.
  Keep `operond start` foreground-only; no ad-hoc daemonization or duplicate
  supervisor is introduced. Define restart/recovery behavior explicitly.
- Introduce a focused Linux backend boundary. Detect the available/usable init
  environment, provide an explicit backend override and test ambiguous/missing
  backends; do not assume every musl host is OpenRC or every glibc host is systemd.
  Preserve existing systemd user-service behavior and public command contracts.
- Make OpenRC system-service scope and required installation/control privileges
  explicit. Never auto-sudo, modify unrelated runlevels/services or implicitly
  create privileged users. Select and validate a non-root daemon identity and
  config/workspace/store paths; root installer identity must not accidentally
  become the daemon identity. Refuse unsafe/ambiguous choices with actionable
  errors. Respect existing config/token permissions; avoid secrets in logs.
- Render safely quoted service configuration with absolute executable/config
  paths, correct working directory/environment and PID/log supervision. Define
  install/boot-enable versus start semantics consistent with existing service
  contracts. Detect config/start failures, readiness, stale process state and
  crashes; command success alone is not proof that the daemon is healthy.
- Stop and uninstall cleanly: wait for supervised daemon shutdown, verify exec
  child cleanup, remove only owned service/runlevel files and never delete user
  configuration, tokens, workspace or persisted state. Support repeatable
  install/uninstall and safely detect conflicting existing service files.
- Test rendering, detection, permission failures, missing OpenRC tools, invalid
  config, status/error/JSON semantics and systemd regression paths. Then execute
  the complete lifecycle with real OpenRC supervision on both Alpine native
  architectures in isolated booted fixtures/VMs; mocked commands are unit tests,
  not live service evidence. Validate boot enablement and restart recovery.
- Document service scope/backend selection, permissions, service identity,
  configuration paths, logs/troubleshooting and manual foreground fallback.
  Keep macOS launchd and Windows SCM behavior unchanged.

Exit criteria: real OpenRC install/start/readiness/status/stop/uninstall, boot
enablement, crash/restart and upgrade/reinstall tests pass on both architectures;
non-root daemon identity and private files remain correct, no orphaned children
or unrelated service changes occur, and existing systemd/native platform tests
pass. Record exact binaries, OpenRC/images/runner versions and lifecycle logs.

## Phase 140: v0.18.25 CI, Install and Release Integration

Status: Planned. Depends on Phases 137–139.

Tasks:

- Extend CI/draft release with both musl archives, static checks, native Alpine
  runtime/live-mount gates and archive smoke before upload. Preserve workspace,
  SDK, CodeQL, glibc and native macOS/Windows gates.
- Update asset sets/SHA256SUMS consistently: new releases have ten assets
  (eight Rust archives, SDK, SHA256SUMS). Older eight-asset releases remain
  verifiable through explicit version/manifest contracts, not optional omissions
  of required musl assets from new releases.
- Add reliable libc/architecture-aware download selection: Alpine selects musl,
  glibc keeps existing assets. Document an explicit override; test unknown or
  ambiguous detection and dry-run output. Keep glibc checks separate from musl.
- Extend downloaded/public verification to Alpine install, foreground daemon,
  real OpenRC lifecycle, artifact integrity and native live mounts. Existing
  systemd service smoke remains; it does not substitute for OpenRC evidence.
- Synchronize README, platform/install docs, PROTOCOL where relevant, decisions,
  repo guidance and validation registration. Replace blanket Alpine-negative
  coverage with musl-positive acceptance; retain a clearly named negative
  glibc-on-Alpine check if useful.
- Make exact-SHA musl gates mandatory in pretag/postrelease orchestration with
  visible failures and retry/idempotence behavior that preserves previous tags.

Exit criteria: full validation groups/native gates pass; new/historical asset
contracts and libc selection are tested; install instructions are verified.
Adding libc builds alone does not require a gRPC schema/protocol compatibility
change. Public package versions align only in actual release preparation.
